## 修复 MCP OAuth 连接失败（WorkBuddy 连接器 Unauthorized）

修 velku四项，跨两个仓库：

- **blunt-serv（本仓库，OAuth 授权服务器）**
  - `app/api/v1/endpoints/oauth.py`：token 端点重写。原来 `code: str = Form(...)` 无条件必填，
    导致 grant_type=refresh_token 必然 422 `loc:["body","code"]`，且完全没有 refresh 分支。
    改为按 grant_type 分支解析（form-encoded + 兼容 JSON），错误体改成 RFC 6749

  - `app/core/security.py`：`create_access_token` 新增可选 `audience` 参数（默认不加 aud，
    以免影响 Web 登录的存量令牌）。
  - `app/core/config.py`：新增 `MCP_RESOURCE_URI`（RFC 8707 resource / JWT aud）与 `CANONICAL_ORIGIN`。
  - `app/api/v1/endpoints/well_known.py`：根路径 PRM 的 resource 由 `https://incremental.icu`
    统一为 MCP 端点 URI，与 /mcp 下元数据、令牌 aud 三者一致。

### 关键坑（务必记住）
1. **PyJWT 陷阱**：`jwt.decode` 不传 audience 而令牌自带 `aud` 时会被判失败。
   所以"签发端先加 aud、校验端还没改"会导致所有新令牌 401 —— 第 4 项必须两端同时上线
   （或校验端先上线）。
2. **t_user_refresh_tokens 没有 scope 列**，refresh 时无法原样恢复 scope；本服务唯一
   scope 是 read，故刷新沿用 read。若要严格"复用原 scope"需加列 + 迁移。
3. **307 的根因**是 Starlette `Mount` 的 path_regex 形如 `/mcp/{path:path}`，匹配不到裸 `/mcp`，
   由上层 Router 的 redirect_slashes 产生重定向；`redirect_slashes=False` 只会变成 404，不能解决。
4. **动态注册客户端存进程内存** `_REGISTERED_CLIENTS`，多 worker 下 register 与 authorize
   落在不同进程会因 redirect_uri 不在 OpenAI 白名单而报"未知的 client_id"。本次未修（超出范围）。
